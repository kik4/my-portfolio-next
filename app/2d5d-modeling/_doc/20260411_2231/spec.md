# 2D顔 × 3Dボディ アニメ表現ツール - 企画書

## 目的

スクリーンスペース的な素直な2D座標系で顔パーツを編集・補間し、それを3Dシーン内のメッシュとしてレンダリングすることで、アニメらしい「2Dの嘘」を保ったまま3Dボディ・髪・複数キャラと合成する。

最終的な移植先は **Unreal Engine** で、製作ツール（本実装）と移植先で **同一のレンダリング仕組み** を使えることを最優先とする。

## 背景となる要求

- 同一シーンに **10体以上のキャラ** を並べる想定（移植先での要件）
- キャラ同士の **前後遮蔽** が必要（手前のキャラが奥のキャラの顔を隠す）
- 3D髪が顔の **前面にかぶる遮蔽** が必要（前髪が目にかかる）
- 製作ツール側ではパフォーマンスは問題にならないが、移植先では問題になる
- 製作ツールと移植先で **同じ仕組み** を採用したい（レンダリングロジックを二重に書きたくない）

## 基本方針

### レンダリング層の選定

ブラウザ固有API（SVG、Canvas2D、DOM）を **顔描画パイプラインから完全に排除** する。顔は最初から Three.js の BufferGeometry + ShaderMaterial で描く。

理由:

- SVG/Canvas2D はブラウザ固有で Unreal に移植できない
- BufferGeometry は頂点バッファと三角形インデックスの抽象で、Unreal の ProceduralMeshComponent / DynamicMeshComponent と 1:1 に対応する
- シェーダは GLSL ↔ HLSL の変換のみで済む

### 編集UIと描画パイプラインの分離

- **編集UI層**: HTML/SVG でよい（点のドラッグ、キーフレーム切替等）。移植しない
- **データ層**: 純粋関数の連鎖（プラットフォーム非依存）。TS で書き、Unreal 移植時に C++ へ翻訳
- **レンダリング層**: Three.js 依存。Unreal 移植時は UE の API に置き換えるが、入力データと出力の見た目は同じになる

### 全パーツを「閉じた点列 = ポリゴン」に統一

顔輪郭・白目・瞳・まつ毛・鼻筋・遮蔽マスク、すべてを **閉じた点列** として持つ。「線」と「塗り」を区別しない。まつ毛や鼻筋のような見た目が線のパーツも、細長い閉じた点列（多角形）として定義する。

これにより:

- 扱うデータ型が1種類（`Polygon`）だけになる
- 処理が1本道（細分割 → 三角形化 → レイヤー合成）
- アニメ的なまつ毛の太さ変化（目頭は細く中央は太く）が点列で自然に表現できる
- エディタUIも全パーツで共通化できる

### パーツを2グループに分ける

顔のパーツを扱い方の異なる2グループに分類する。

**輪郭グループ**: 顔輪郭・鼻・頬など、ヨー/ピッチで形状そのものが変わるパーツ。
- 正面 (yaw=0, pitch=0) の点列をベースとして持つ
- (yaw, pitch) 平面上に配置された **形状差分キーフレーム** を持つ
- さらに **ブレンドシェイプ**（正面空間での変形バリエーション）も持つ

**フィーチャーグループ**: 顔面に貼られる 2D デカールとして扱うパーツ。目・口・瞳・ハイライト・眉・まつ毛・瞼・鼻線・頬紅・フェイスペイント・泣きマーク・汗など、種類はデザインに応じて増える。
- 正面の点列をベースとして持つ
- ヨー/ピッチに対しては「移動と変形と可視性」だけをキーフレームとして持ち、形状そのものは変えない
- ヨー/ピッチキーフレームは (yaw, pitch) 平面上に配置された **アフィン変換パラメータ**（position + 2x2行列）と **α 値** を保持
- さらに **ブレンドシェイプ**（瞬き、笑み、口の開閉、照れで頬紅が出る、など）を持ち、ブレンドシェイプも形状差分に加えて α 差分を持てる

この分割の目的:

- 目・口は正面形状1つだけを作り込めばよく、ヨー/ピッチ全方位にアニメ差分を作る必要がなくなる
- 瞬きや口パクのアニメーションはブレンドシェイプで一元的に表現できる
- 作業量が大幅に削減される
- 輪郭グループだけは形状変化が必要なので、作り込みの手間をそこに集中できる
- 数を増やしやすい（フェイスペイント、泣きマークなど後からデザイン要素を追加しやすい）

### 鼻の二重構造

鼻は見え方が2通りあり、両グループにまたがる珍しい例になる:

- **輪郭グループの鼻シルエット**: 斜め顔で顔輪郭から突き出る鼻の立体形状。正面では差分ゼロ（ほぼ見えない）、横向きキーフレームで突き出る
- **フィーチャーグループの鼻線**: 正面や軽い斜め顔で鼻筋を示すための細長いデカール。正面で α = 1、横向きキーフレームで α = 0 にフェードさせる

両者はキーフレームの α と差分を相補的に設定することで自動的に切り替わる。

### ヨー/ピッチキーフレームの空間

輪郭グループ・フィーチャーグループいずれも、ヨー/ピッチキーフレームは **(yaw, pitch) 2次元平面上に配置** される。補間は既存実装を流用した **2次元 RBF 補間** を使う。

- キーフレームを規則的な格子に置く必要はなく、必要な向き（正面、右 30°、右 60° + 上 20° など）にピンポイントで配置できる
- 正面 (0, 0) はキーフレームとしては持たず、ベースそのものが (0, 0) を担当する
- キーフレームは「正面ベースからの差分」を保持する（絶対値ではない）

## データ構造

### 基本型

```ts
type Point2D = [number, number];
type ColorRGBA = [number, number, number, number];

// ヨー/ピッチ座標（度）
interface YawPitch {
  yaw: number;
  pitch: number;
}

// 2x2 アフィン変換（scale, shear, rotation を包含）
type Mat2 = [number, number, number, number]; // [m00, m01, m10, m11]

// 輪郭グループ用のブレンドシェイプ
interface OutlineBlendShape {
  id: string;               // "cheek_puff" など
  deltas: Point2D[];        // ベース点列と同じ長さ。各点の差分
}

// フィーチャーグループ用のブレンドシェイプ
// 形状差分に加えて α の差分を持ち、「照れで頬紅が出る」「泣きで涙マークが現れる」等を表現する
interface FeatureBlendShape {
  id: string;               // "blink", "smile", "blush" など
  deltas: Point2D[];        // ベース点列と同じ長さ。各点の差分
  alphaDelta: number;       // α への加算差分。0 なら不透明度は変えない
}

// 輪郭グループのポリゴン
interface OutlinePolygon {
  id: string;
  group: "outline";
  basePoints: Point2D[];    // 正面 (0, 0) でのベース点列
  layerIndex: number;
  fillColor: ColorRGBA;

  blendShapes: OutlineBlendShape[];

  // (yaw, pitch) 平面上のキーフレーム。各キーフレームは deltas を持つ
  yawPitchKeyframes: {
    angle: YawPitch;
    deltas: Point2D[];      // basePoints と同じ長さ。正面からの差分
  }[];

  // 事前焼き込み済み三角形インデックス（earcutハイブリッド用）
  triangleIndices?: number[];
}

// フィーチャーグループのポリゴン
interface FeaturePolygon {
  id: string;
  group: "feature";
  basePoints: Point2D[];    // 正面での形状（これだけ持つ）
  layerIndex: number;
  fillColor: ColorRGBA;
  baseAlpha: number;        // 基本の不透明度（通常 1.0）

  groupId?: string;         // 所属する FeatureGroup の id（未指定なら単独）

  blendShapes: FeatureBlendShape[];

  // (yaw, pitch) 平面上のキーフレーム。各キーフレームはアフィン変換 + α を持つ
  // ここでの変換はグループ変換の「内側」で作用する（目の中でのハイライトのズレなど）
  yawPitchKeyframes: {
    angle: YawPitch;
    position: Point2D;      // 平行移動
    matrix: Mat2;           // 2x2 アフィン
    alpha: number;          // この向きでの不透明度（0〜1、連続補間）
  }[];

  triangleIndices?: number[];
}

// フィーチャーグループ（ポリゴンを束ねる親ノード）
// 「目全体」「口全体」のような単位で位置・変形・可視範囲・描画順を一元管理する
interface FeatureGroup {
  id: string;               // "leftEye", "rightEye", "mouth" など

  // (yaw, pitch) 平面上のキーフレーム。グループ配下のポリゴン全体に作用する変換
  yawPitchKeyframes: {
    angle: YawPitch;
    position: Point2D;
    matrix: Mat2;
  }[];

  // グループ可視範囲（矩形、間なしの on/off 判定）
  // キャラローカル (yaw, pitch) がこの範囲外なら配下ポリゴンを描画しない
  visibility: {
    yawRange: [number, number];
    pitchRange: [number, number];
  };

  // グループ配下のポリゴンに適用される基本 layerIndex
  // 配下ポリゴンの layerIndex はこの値への加算オフセットとして扱われる
  baseLayerIndex: number;

  // 向きに応じた layerIndex の上書き（最近傍選択、補間しない）
  // 左目が左向きで手前、右向きで奥、のような切り替えに使う
  layerIndexKeyframes?: {
    angle: YawPitch;
    layerIndex: number;
  }[];
}

type Polygon = OutlinePolygon | FeaturePolygon;

// キャラ全体のデータ
interface FaceModel {
  polygons: Polygon[];
  featureGroups: FeatureGroup[];

  // 実行時の状態（編集UIやアニメから与える）
  blendShapeWeights: Record<string, number>; // "blink" → 0.8 など
}
```

ポイント:

- **ベースと差分の分離**: 正面ベース点列を1つ持ち、ブレンドシェイプもヨー/ピッチキーフレームもすべて「ベースからの差分」として保持する。これにより両者を加法的に合成できる
- **group フィールドで分岐**: 輪郭グループとフィーチャーグループは構造が違うので discriminated union で分ける
- **ブレンドシェイプは各ポリゴン固有**: 目には目のブレンドシェイプ、口には口のブレンドシェイプ、顔輪郭には顔輪郭のブレンドシェイプが紐づく
- **α はフィーチャーポリゴンにのみ存在**: 輪郭グループは顔の立体感そのものなので常に不透明。フィーチャーグループのポリゴンは顔面に貼られるデカール的扱いで、向きや表情で可視性を連続的に制御する
- **α の合成は乗算**: 最終 α = `baseAlpha × (ヨー/ピッチ補間 α) × (1 + Σ FeatureBlendShape.alphaDelta × weight)` のように複数の α 寄与を乗算で合成する（詳細は後述）
- **FeatureGroup は変換と可視範囲と描画順**: フィーチャーグループのポリゴンを束ねる親ノードとして `FeatureGroup` を導入する。グループは「目全体を動かす」ための階層的アフィン変換、「横顔で目が完全に消える」ための矩形可視範囲、「左向きで右目が奥、右向きで右目が手前」のような向き依存の layerIndex 上書きを持つ。ブレンドシェイプと α は持たず、ポリゴン側に一元化する
- **グループ配下ポリゴンの layerIndex は加算オフセット**: グループに所属するフィーチャーポリゴンの `layerIndex` は絶対値ではなく、グループの `baseLayerIndex`（または `layerIndexKeyframes` で上書きされた値）への **加算オフセット** として解釈される。例: 左目グループの baseLayerIndex=2、瞳ポリゴンの layerIndex=1 なら、瞳の実効 layerIndex は 3。グループ自体の layerIndex が切り替わると配下ポリゴンの実効 layerIndex も一斉に切り替わる
- **layerIndex は最近傍選択**: `layerIndexKeyframes` は RBF 補間せず、現在の (yaw, pitch) から **最も近いキーフレームの layerIndex** を採用する（ステップ切替）。整数性を保ち深度バッファとの整合を単純にする。切り替わり境界は鼻遮蔽マスクの下で起きるため視覚的に目立たない
- **グループ階層は1段のみ**: グループ配下のポリゴンは別グループに再帰的に所属できない。シンプルさを優先する
- **ID 連動ブレンドシェイプ**: 「目全体を閉じる」のような一括変形は、上瞼・白目・瞳・ハイライト等が同じ `id`（例: `"blink"`）のブレンドシェイプを個別に持ち、`FaceModel.blendShapeWeights[id]` の重みで同時に動くことで実現する（グループにブレンドシェイプを持たせる必要はない）
- **ブレンドシェイプの重みはキャラ全体で共有**: 重みは `FaceModel.blendShapeWeights` に集約され、各ポリゴンが同じ `id` のブレンドシェイプを持っていれば連動する（例: 「笑顔」重みで目と口と頬が同時に動く、という表現ができる）

### レイヤー順の例

実際のパーツ構成はデザインに依存するが、一例を示す。

| layerIndex | 想定パーツ | グループ |
|---|---|---|
| 0 | 顔輪郭（肌色塗り） | outline |
| 1 | 頬の膨らみ | outline |
| 1 | 鼻シルエット（横向きで現れる） | outline |
| 1 | 遮蔽マスク（奥目をヨー時にクリップ） | outline |
| 2 | 白目 | feature |
| 3 | 瞳（虹彩） | feature |
| 4 | 黒目（瞳孔） | feature |
| 5 | ハイライト | feature |
| 6 | 上瞼（肌色） | feature |
| 6 | 下瞼（肌色） | feature |
| 7 | 上まつ毛 | feature |
| 7 | 下まつ毛 | feature |
| 5 | 口 | feature |
| 5 | 鼻線（正面で現れる） | feature |
| 5 | 眉 | feature |
| 5 | 頬紅 | feature |
| 8 | フェイスペイント | feature |
| 9 | 泣きマーク・汗など | feature |

同一 layerIndex 内での描画順は配列順に従う。

瞼は白目・瞳より手前（大きい layerIndex）に置くことで、`"blink"` ブレンドシェイプで瞼が閉じたときに白目・瞳を覆い隠せる。同じ `"blink"` ID を白目・瞳・まつ毛側にも用意し、瞼の閉じに合わせて連動変形させるのが自然。

### 左右目の描画順入れ替え

向きに応じて奥目と手前目の描画順を入れ替える要求（向かって左向き: 右目 → 鼻遮蔽 → 左目、向かって右向き: 左目 → 鼻遮蔽 → 右目）は、FeatureGroup の `layerIndexKeyframes` で実現する。

| グループ/ポリゴン | baseLayerIndex | layerIndexKeyframes |
|---|---|---|
| 鼻遮蔽マスク（輪郭グループ） | 3 | - |
| leftEye グループ | 2 | 左向き (-30〜-90, 0) で 5、右向き (30〜90, 0) で 2 |
| rightEye グループ | 2 | 右向き (30〜90, 0) で 5、左向き (-30〜-90, 0) で 2 |

向きによる切り替わり:

- 正面付近: 両目とも 2（鼻遮蔽 3 の下）。通常の表示
- 向かって左向き: 右目 = 2（奥）、鼻遮蔽 = 3（中間）、左目 = 5（手前）
- 向かって右向き: 左目 = 2（奥）、鼻遮蔽 = 3（中間）、右目 = 5（手前）

切り替わり境界は鼻遮蔽マスクの下で起きるため視覚的に目立たない。

単独ポリゴン（グループに属さないフィーチャーポリゴン）は `layerIndexKeyframes` を持たず、固定の layerIndex で描画される。向き依存の描画順入れ替えが必要なら、そのポリゴンを1つだけ含む FeatureGroup を作る。

### 目の構成要素

目は複数のフィーチャーポリゴンの集合として構成する。構成要素の例:

- 上瞼（肌色、白目を覆ってブリンクを作る）
- 下瞼（肌色）
- 上まつ毛のライン
- 下まつ毛のライン
- 白目
- 瞳（虹彩）
- 黒目（瞳孔）
- ハイライト

これらを独立したポリゴンに分けることで、まつ毛は黒、瞼は肌色、といった色の差を自然に扱える。瞼を閉じる `"blink"` ブレンドシェイプを上瞼・上まつ毛・白目・瞳・黒目・ハイライトそれぞれに用意し、同一 ID で重みを共有すれば、目全体が連動してブリンクする。

瞳・ハイライトなどの内部構成は **キャラデザインに依存** する。瞳を単色にするキャラ、虹彩のグラデーションを複数レイヤーで表現するキャラ、十字ハイライトを持つキャラなど、必要に応じてポリゴン数を増減できる。

### 左右の目の扱い

左右の目は **独立したポリゴン群** として持つ。左右共通形状＋変換で持つ方式は採用しない。理由:

- 塗り分け（白目/瞳/まつ毛/瞼）を展開すると組み合わせが爆発する
- 左右で微妙に違う形（ウインク、片目つぶり）が自然に扱える
- 移植時のデータ構造が素直
- 左右対称作成はエディタ機能（ミラー編集ボタン）で解決する

### 横向き時の目・口の遮蔽

フィーチャーグループ（目・口）はヨー/ピッチで形状が変わらずアフィン変換だけで位置調整されるため、横向き時に奥側の目が顔輪郭から飛び出す懸念がある。これは次の2つの併用で解決する。

- **遮蔽マスク**: 肌色塗りの輪郭グループポリゴンを、奥側の目の上に重ねて置く。遮蔽マスク自体は輪郭グループなのでヨー/ピッチで形状が変わり、横向きが進むにつれて奥目を覆うように変形する
- **位置移動**: フィーチャーグループのキーフレームで、目の `position` を顔輪郭の内側に収まるように動かす

## データ層の処理フロー

すべて純粋関数の連鎖。入力は `FaceModel` と現在の `(yaw, pitch)` と `blendShapeWeights`。

### 輪郭グループのポリゴン

```
basePoints
  ↓ ブレンドシェイプ適用（各 BlendShape.deltas × weight を加算）
ブレンド後の正面点列
  ↓ (yaw, pitch) キーフレームを2次元RBFで補間して差分を算出
形状差分
  ↓ ブレンド後の正面点列に差分を加算
最終点列
```

### フィーチャーグループのポリゴン

まずグループの可視範囲で描画の on/off を決める:

```
ポリゴンが FeatureGroup に所属している場合:
  現在の (yaw, pitch) が group.visibility の矩形外
    → 配下のポリゴンを描画スキップ（頂点を生成しない）
    → 間なしの on/off。補間による中間状態は生じない
  矩形内
    → 以下の処理に進む
```

矩形内のポリゴン処理:

```
basePoints
  ↓ ブレンドシェイプ適用（deltas の重み付き加算）
ブレンド後の正面点列
  ↓ ポリゴンの (yaw, pitch) キーフレームを2次元RBFで補間して
    (posLocal, matLocal, alphaLocal) を算出
  ↓ 所属グループがあれば、グループの (yaw, pitch) キーフレームを補間して
    (posGroup, matGroup) を算出。なければ単位変換
  ↓ 変換合成:
    matFinal = matGroup * matLocal
    posFinal = matGroup * posLocal + posGroup
  ↓ 各点に matFinal * p + posFinal を適用
最終点列

α の合成（別経路で並行計算）:
  alpha_blend = 1 + Σ (FeatureBlendShape.alphaDelta × weight)   // クランプ [0, 1]
  alpha_final = baseAlpha × alphaLocal × alpha_blend            // クランプ [0, 1]

実効 layerIndex の決定（別経路）:
  if group.layerIndexKeyframes に現在の (yaw, pitch) に近いキーフレームあり:
    groupLayer = 最近傍キーフレームの layerIndex  // 補間せずステップ選択
  else:
    groupLayer = group.baseLayerIndex
  polygonEffectiveLayer = groupLayer + polygon.layerIndex       // 加算オフセット
```

- **グループの可視範囲**: ステップ判定による間なし on/off。横顔での目グループ消失などに使う
- **ポリゴン α**: RBF による連続補間。鼻線のフェード、頬紅の薄さなどに使う
- **グループの layerIndex 上書き**: 最近傍選択によるステップ切替。左目・右目が向きに応じて奥/手前を入れ替えるのに使う
- 三者は独立の仕組みで干渉しない

α は頂点カラーの A チャンネルとして BufferGeometry に書き込み、フラグメントシェーダでアルファテストに使う。α が閾値（0.5）未満の三角形は Masked により破棄される。

フィーチャーグループは概念的に **「顔面に貼られた 2D デカール」** として扱う。目・口・瞳・ハイライト・眉・鼻線・頬紅・フェイスペイント・泣きマーク・汗などすべて同じ型で、数を増やしても設計は破綻しない。

### グループ変換による立体感演出

ハイライトや瞳などの目の構成要素は、FeatureGroup の変換（目全体の動き）に加えて、ポリゴン固有の (yaw, pitch) キーフレームで微小なズレを持たせることができる。目全体が画面右にスライドするのに加え、ハイライトだけがさらに数ピクセル右にずれる、といった階層的な動きで立体感を出せる。

### 共通の後段

```
各ポリゴンの最終点列
  ↓ Catmull-Rom 細分割（全ポリゴン共通）
細分割済み点列
  ↓ earcut 三角形化（焼き込み済みインデックスがあればそれを使用）
三角形群（layerIndex 付き）
  ↓ layerIndex 順に並べてローカル Z オフセット付与
頂点配列 + インデックス配列 + 頂点カラー
```

この出力を BufferGeometry（Unreal では ProceduralMeshComponent）に詰める。

### 2次元 RBF 補間について

- 入力: キーフレーム群 `[(yaw_i, pitch_i) → value_i]`、クエリ `(yaw, pitch)`
- 出力: 補間された value
- value は輪郭グループでは点列の差分（各点が独立）、フィーチャーグループではアフィン変換パラメータ（position 2成分 + matrix 4成分）
- 距離関数はユークリッド距離（度を単位として）
- RBF カーネルは既存実装と同じものを流用（Gaussian か thin-plate spline）

焼き込み済み三角形インデックスは点の **位置** には依存しないので、ブレンドシェイプやヨー/ピッチ補間で点がどう動いても再利用できる（位相が変わらないため）。

### Catmull-Rom 細分割

閉じた点列を滑らかな曲線に補間する。制御点は位置のみ。ハンドルなし。自前実装（軽量）。

### earcut 三角形化

閉じた多角形をインデックス配列（三角形群）に変換する。

**ハイブリッド方式** を採用する:

- 編集時は実行時 earcut（編集体験をなめらかに保つ）
- 保存時にインデックスを焼き込んで JSON に含める
- 移植先（Unreal）では焼き込み済みインデックスを使うので、TS と C++ の earcut 実装差による見た目ズレが発生しない

## レンダリング層の設計

### 顔メッシュ = 単一の Masked マテリアル

顔全体（顔輪郭＋目＋まつ毛＋鼻筋＋遮蔽マスク）を **単一のメッシュ** として扱う。マテリアルは半透明ではなく **アルファテスト（Masked）** を使う。

なぜ半透明ではないか:

- 半透明は深度バッファに書き込まないため、複数キャラ・前髪との前後関係がソート頼みになり破綻する
- Masked なら閾値以上のピクセルは不透明として深度に書き込み、前髪や他キャラとの前後が深度バッファで自動解決される

縁のジャギ対策は **MSAA 任せ** とする:

- Three.js 側はレンダラの `antialias: true`（MSAA）に任せる
- Unreal 側もプロジェクト設定の MSAA / TemporalAA に任せる
- シェーダ内での SDF 風アンチエイリアスは実装しない（実装負荷を下げる）
- MSAA で不足する場合は将来の改善項目とする

### レイヤー内合成: ローカル Z オフセット

目・瞳・まつ毛などの重なりを半透明レイヤーで処理しない。代わりに各レイヤーにわずかに異なる **板ポリローカル Z** を与え、深度バッファで重なりを解決する。

- オフセット量: 0.001 〜 0.01 程度（視覚的に分離できて、かつ深度精度内）
- ローカル Z なので板ポリの向きに依存せず、カメラが動いてもレイヤー順が安定する
- 板ポリを真上から見るとオフセットが潰れるが、通常そのような視点にはならない

これにより顔というオブジェクトは「単一の Masked メッシュ」として振る舞い、前髪・他キャラとの前後関係が正しく解決される。

### 板ポリの配置

- 各キャラのワールド位置に顔メッシュを配置
- メッシュは **カメラに正対** させる（Billboard）
- ただし「板ポリがカメラに正対」なのであって、顔の向きそのものは Yaw/Pitch で中身の点列が変化することで表現する

### ヨー角の算出（複数キャラ対応）

顔パーツの補間に渡す yaw は「カメラのワールド yaw」ではなく **キャラのローカル座標系でカメラを見た角度** で計算する。

```
yawLocal = atan2(
  (camera.position - character.position).x_in_character_local,
  (camera.position - character.position).z_in_character_local
)
```

これによりキャラ A が画面左、キャラ B が画面右でそれぞれ別方向を向いている状況でも、各キャラの顔が正しく補間される。

### カメラ距離によるスケール

板ポリはシーン内の透視カメラで描画されるため、遠いキャラの顔は自動的に小さく写る。現行 spec にあった `baseSize * (baseDistance / cameraDistance)` の手動スケール計算は **不要**。

## 前髪遮蔽の取り扱い

- 前髪は 3D メッシュとして通常通りレンダリング
- 顔は Masked メッシュとして不透明扱い
- 深度バッファにより「前髪の前に顔が来るピクセル」「顔の前に前髪が来るピクセル」が自動解決
- 追加のソート処理は不要

## 参考3Dモデル

編集中に顔の輪郭・目・鼻・口などの位置を確認するための **ガイド** として、3Dの頭モデル（`base2.glb` 等）をシーン内に表示する機能を持つ。Unreal移植時には不要（編集UIはUE側に存在しないため）で、製作ツール固有の機能。

### 役割

- 顔ポリゴンを描く位置・大きさの基準となる立体ガイド
- 編集中の (yaw, pitch) に合わせて参考モデルが見えることで、その向きでの正しい顔形状を確認しながら点列を編集できる
- 顔ポリゴン（板ポリ Billboard）と同じワールド位置に重なって表示される

### 表示仕様

- glb / gltf を `useGLTF` でロード
- マテリアルは `MeshBasicMaterial` に置き換える（陰影を消し、輪郭・特徴点を見やすくする）
- **opacity 調整可能**（スライダー等で 0〜1）。顔ポリゴンとの重なりを編集者が見やすい透明度に調整する
- **表示/非表示トグル**: 完成形の確認時には参考モデルを消したい
- 頭部中心を原点付近に揃えるオフセット計算（バウンディングボックスから中心を算出して位置補正）。これがないとキャラのワールド位置と頭部の位置がずれる

### カメラとの関係（旧実装からの変更）

旧実装は「参考モデル専用の Canvas + スライダーで角度指定 → カメラが球面上を動く」だったが、新実装ではキャラ本体シーンに参考モデルを共存させる方式に変える:

- ユーザは **OrbitControls でメインシーンのカメラを動かす**
- カメラの向きから各キャラのローカル (yaw, pitch) が決まる
- 参考モデルはキャラのワールド位置に固定配置されるだけ（向き自体は動かさない）
- カメラが動くことで、参考モデルと顔ポリゴンが同じ向きから見える

つまり「参考モデルの向きを操作する」のではなく「カメラを動かすことで結果的に向きが変わる」UIになる。

### 配置

- 各キャラのワールド位置に1体ずつ参考モデルを配置（複数キャラ対応）
- 顔ポリゴンの板ポリと同じ座標を共有することで、編集中の顔ポリゴンが参考モデルの顔面に重なって見える
